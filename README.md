# gg — Google Workspace ドメインチェック

Chrome / Edge 用の拡張機能（検証版 v0.1）です。希望ドメインを入力するとGoogle Workspaceの申込画面を操作し、確認画面で停止します。その先のアカウント作成・契約は行いません。

## ダウンロードせず、コピーして導入

1. デスクトップに `gg` フォルダを作成します。
2. 下表のファイルをGitHubで開き、コードだけをコピーして同じ名前で保存します。行番号は含めません。
3. メモ帳では「ファイルの種類：すべてのファイル」「文字コード：UTF-8」を選び、末尾に `.txt` が付かないようにしてください。
4. `tests/core.test.cjs` のみ、gg内に `tests` フォルダを作り、その中に保存します。他の8ファイルはgg直下です。
5. Chromeで `chrome://extensions`、Edgeで `edge://extensions` を開き、デベロッパーモードを有効にします。
6. 「パッケージ化されていない拡張機能を読み込む」で `gg` フォルダを選択します。
7. 拡張機能の **gg** をクリックし、ドメインを入力してチェックします。

| ファイル | 用途 |
|---|---|
| [manifest.json](manifest.json) | 拡張の設定・権限 |
| [background.js](background.js) | 実行管理・タイムアウト |
| [content.js](content.js) | 申込画面の自動操作 |
| [core.js](core.js) | ドメイン検証・判定 |
| [index.html](index.html) | 入力画面 |
| [style.css](style.css) | デザイン |
| [ui.js](ui.js) | 入力画面の処理 |
| [README.md](README.md) | この手順書 |
| [tests/core.test.cjs](tests/core.test.cjs) | 開発用テスト |

合計9ファイル。動作に必要なのは最初の7ファイルです。Node.js・Python・サーバー・APIキーは利用時には不要です。Chrome / Edge 112以上を想定しています。会社管理ブラウザで拡張の導入が制限されている場合は管理者による配布・許可が必要です。

## 判定の意味

| 結果 | 条件 |
|---|---|
| チェックOK | 今回送信したタブで正規URLの `/business/signup/bringconfirm` に到達し、対象ドメインとメールへの影響がない旨の確認文言が一致 |
| 既存利用の表示あり | 対象ドメインについて「このドメイン名はすでに使用されています」または「既存のサブスクリプションが見つかりました」を確認 |
| 未確認 | 120秒のタイムアウト、想定外の画面、照合不一致、タブ閉鎖、手動停止、人による確認など |

**チェックOKは、この申込フローで確認画面まで進めたという意味です。既存テナントが絶対に存在しないこと、ドメイン所有権、契約可能性を保証しません。** Cloud Identity等を含む厳密なテナント照会ではなく、MXレコードによる推測もしません。

## 読み取り・書き込み・外部送信

ソースに実在顧客の情報、パスワード、APIキーは含みません。ただし、動作のため以下の処理を行います。

| 処理 | 範囲 |
|---|---|
| 読み取り | 実行用タブのGoogle Workspace申込ページの表示テキスト・フォーム入力値 |
| 入力・送信 | 希望ドメイン・会社名・連絡先をGoogleの申込フォームに入力し、次へを操作 |
| 一時保存 | 実行設定、対象ドメイン、結果、日時を拡張のセッション領域に保持 |
| PC内のファイル | 読み取り・書き出し処理なし |
| その他 | 他サイトの情報収集、Cookie取得、閲覧履歴取得、独自サーバーへの送信処理なし |

初期値は会社名・姓・名が `test`、連絡先が予約例示ドメインの `test@example.com`、従業員数10〜99人です。Googleに拒否された場合は設定欄で自社の使用可能な連絡先に変更してください。申込画面に連絡先が入力済みなら維持します。地域が日本と認識できない場合は先へ進めません。

履歴は蓄積せず、最新の入力と結果のみブラウザ終了等まで保持します。Google側の保存はGoogleの取扱いに従います。実行は1件ずつで、大量一括照会・連続リトライはありません。拡張が作成したタブだけを操作します。実行中はそのタブを手動操作しないでください。停止直前に発火済みの操作は取り消せません。

## 移行・GAS

フォルダ全体を別PCへコピーして同じ手順で導入できます。絶対パス・特定アカウント・特定サーバーには依存しません。ただしChrome/Edgeの拡張APIとGoogleの画面構造には依存します。

GASのUrlFetchAppはHTTP取得機能であり、ブラウザとしてJavaScriptやDOM操作を実行するものではありません。GASのHTML画面から別オリジンの申込画面も直接操作できません。そのためGAS単体は採用していません。GASを入口にする場合も別途ブラウザ操作機構が必要です。非公開の内部APIやセッショントークンの再現は実装していません。

## 検証と制限

2026-11-12の作成作業で日本語の実画面を手動操作し、welcome → contact → signuptypeselect → bring → bringconfirm の遷移を確認しました（例示用 `example.com`、アカウント作成は未実施）。

判定ロジックの単体テスト8件は合格しています。**拡張をChromeにインストールした状態での一連の実行は未検証です。** 既存利用の2パターンは指定文言に基づく単体テストで確認しています。最初に状態を把握しているドメインで照合してください。

人による確認、ログイン要求、入力拒否、通信障害、画面変更では未確認になります。日本語以外の画面は未対応です。画面変更時は主に `content.js` の修正が必要です。開発用テストは `node --test tests/core.test.cjs` で実行できます。
